# Phase 01: Feasibility Check and High Glucose Soon Alert Engine

This phase confirms that "High Glucose Soon" can be built as a straight mirror of the existing "Low Glucose Soon" alert, then adds the new `forecastedHigh` alert type end to end through the model, forecast evaluator, coordinator, store, and editor view so the app compiles with a fully functioning alert. By the end, a forecasted +20 minute glucose at or above 270 mg/dL will fire a "High Glucose Soon" alarm (once the user enables it), and the branch `dave/alerts` builds cleanly for the test scheme. Tracks GitHub issue nightscout/Trio#1594. Decisions already locked in: default threshold 270 mg/dL (matches the existing `high` default), default sound `bloom.caf`, default disabled (per Dan on Discord), suppressed while a `high` alarm is already firing, and the forecast path keeps its existing no-CGM-ownership-guard reasoning.
